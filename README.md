Структура Dataflash логов ArduPilot

Dataflash логи — это бинарные файлы, которые записываются на SD-карту полётного контроллера (Pixhawk, Cube и др.). Они содержат детальную телеметрию и диагностику для анализа полётов.

Основные компоненты структуры:

• Заголовок (Header)
Первые несколько килобайт файла. Содержит метаданные:
– Версию формата лога (FMT, версия сообщений).
– Информацию о прошивке: тип (ArduCopter, Plane), версия, git-хэш.
– Описание форматов всех сообщений (FMT-сообщения), которые будут встречаться в логе.

• Блоки данных (Data Blocks)
Основная часть файла. Состоит из последовательности записей (сообщений). Каждое сообщение имеет:
– Заголовок сообщения (обычно 3 байта): идентификатор типа сообщения и его длина.
– Полезную нагрузку: данные, соответствующие формату, определённому в заголовке.

Ключевые типы сообщений (Message Types, MSG):

• FMT – самый важный тип. Определяет формат других сообщений. Содержит:
– Название сообщения (например, "GPS").
– Длину записи.
– Формат полей (набор символов: 'f' – float, 'I' – uint32t, 'Q' – uint64t, 'i' – int32t, 'h' – int16t, 'c' – int16t  0.1, 'b' – int8t, 'B' – uint8t, 'n' – char[4], 'N' – char[16], 'Z' – char[64], 'M' – uint8t, 'e' – int32_t  0.01).
– Заголовки полей (названия столбцов через запятую).

• Параметры (PARM) – записывает все имена и значения параметров на момент взлёта (arming).

• Данные сенсоров и состояния – основная телеметрия. Примеры:
– GPS: время, широта, долгота, высота, скорость, количество спутников, HDOP.
– IMU, IMU2, IMU3: сырые и отфильтрованные данные с инерциальных датчиков (ускорения, гироскопы).
– ATT: углы ориентации (Roll, Pitch, Yaw).
– CTUN: данные контроллера (желаемые и текущие углы, высота, throttle).
– NTUN: навигационные данные (целевые и фактические позиции, скорость).
– MODE: текущий режим полёта (например, Stabilize, AltHold, Auto).
– CMD: выполняемая команда миссии.
– EV: события (арминг, дизарминг, изменение режима).
– MSG: текстовые сообщения для отладки.

• Периодичность
Частота записи разных сообщений разная. Быстрые данные (IMU, ATT) пишутся с высокой частотой (десятки Гц), навигационные и событийные данные (GPS, MODE, EV) — реже (несколько Гц).

Как работать с логами:

1. Просмотр и анализ
Используй официальные инструменты:
– Mission Planner (Windows) → вкладка "Flight Data" → "Log Analysis".
– MAVExplorer (кроссплатформенный, входит в комплект Mission Planner).
– Онлайн-анализатор: https://plot.ardupilot.org.

2. Парсинг программно
Для автоматического анализа можно использовать библиотеку pymavlink (модуль DFReader).

```python
from pymavlink import mavutil

# Загрузка лога
log = mavutil.mavlink_connection('logfile.bin', dialect='ardupilotmega')

# Чтение всех сообщений определённого типа
gps_messages = []
while True:
    msg = log.recv_match(type=['GPS'], blocking=False)
    if msg is None:
        break
    gps_messages.append(msg)

# Доступ к полям первого сообщения GPS
if gps_messages:
    first_msg = gps_messages[0]
    print(f"Lat: {first_msg.Lat}, Lon: {first_msg.Lng}, Alt: {first_msg.Alt}, Sats: {first_msg.NSats}")
```

Важные нюансы:

• Логи пишутся в циклический буфер. При заполнении карты старые логи перезаписываются.
• Для анализа критических сбоев (падений) ищи логи с префиксом "APM" (для старых версий) или последний файл после инцидента.
• В настройках параметров (LOG_BITMASK) можно выбрать, какие типы сообщений записывать, чтобы уменьшить размер лога.
